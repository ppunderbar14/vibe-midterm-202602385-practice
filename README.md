# vibe-midterm-202602385-practice
중간고사 연습용 메뉴·의사결정 룰렛

## 현재 진행 상태

**5단계 저장·프리셋 구현 및 브라우저 검사 완료, 최종 점검·배포 전**

후보를 추가·삭제하고 이름·가중치·색상을 편집할 수 있다. 입력 검증 후 가중치 비율에 맞춘 원판과 선택 확률을 표시하며, 회전이 감속해 멈춘 뒤 화살표 아래 조각 이름을 결과로 보여준다. 현재 후보를 자동 저장·복원하고 프리셋을 저장·불러오기·삭제할 수 있다.

## 앱 소개

메뉴나 선택지를 등록하고 룰렛을 돌려 하나를 고르는 정적 웹앱이다. 후보별 가중치에 따라 선택 확률과 원판 조각 크기를 다르게 설정할 수 있다. HTML, CSS, JavaScript와 Canvas 2D만 사용하며 외부 라이브러리나 빌드 도구는 사용하지 않는다.

## 저장 방식

앱 전용 키 `vibeRoulette:v1`의 버전 1 JSON에 현재 후보와 프리셋을 저장한다. 유효한 후보 변경과 프리셋 작업 뒤 저장하며, 프리셋은 후보 목록의 복사본이다. 후보는 0~20개를 저장할 수 있고 2개 미만이면 회전을 막는다.

복원 시 버전·구조·ID·이름·가중치·색상·개수를 검증한다. 손상 데이터는 기본 후보로 시작하고 로드만으로 원본을 덮어쓰지 않는다. 이후 사용자가 유효한 후보나 프리셋을 변경하면 새 상태를 저장한다. 저장소 접근·쓰기 실패 시 현재 화면은 계속 사용할 수 있지만 새로고침 후 변경이 유지되지 않을 수 있다. 다른 앱의 저장 키는 변경하지 않는다.

## 최종 수정본 브라우저 확인 (2026-10-15)

- `06904e5`의 로컬 파일을 별도 임시 Chrome(헤드리스)에서 열고 캐시를 무시해 새로고침했다. 기존 열린 Chrome 탭 연결은 `Unable to load browser request-header policy` 오류로 실패했다.
- 무작위 6회 중 5회는 화살표 아래 Canvas 색상과 결과가 일치했다. 1회는 색상 표본이 흰색 조각 경계선에 걸려 판정 불가였으며, 불일치로 단정하지 않았다.
- 재현 가능한 난수 0.125·0.375·0.625·0.875·0.2·0.7을 지정해 실제 4.2초 애니메이션을 6회 추가 실행했다. 한식·중식·일식·양식·한식·일식 순서로 화살표 아래 Canvas 색상과 결과 문구가 모두 일치했다. 난수 지정은 검사 브라우저에만 적용했고 앱 코드는 바꾸지 않았다.
- 매 회전마다 빠른 클릭 5회에도 시작은 1회였고, 회전 중 후보 입력·추가·삭제가 잠겼다. 종료 후 잠금 해제와 실제 후보 추가·이름 수정·삭제를 확인했다.
- 데스크톱 1280px에서 두 열, 360px에서 한 열 화면을 캡처해 확인했다. 360px에서 `document.documentElement.scrollWidth === clientWidth === 360`, `document.body.scrollWidth === 360`으로 가로 스크롤이 없었다. 입력·버튼·선택의 최소 높이는 44px이고 footer도 정확했다.
- 검사 페이지의 JavaScript 예외·`console.error`·브라우저 오류 로그는 0건이었다. Chrome 자체 실행 로그의 디스플레이·백그라운드 서비스 경고는 페이지 JavaScript 오류와 구분했다.
- 기존 열린 Chrome 탭 자체의 새로고침·직접 조작은 연결 오류로 미확인이다. 별도 Chrome에서 요청한 기능 검사를 마쳤으며, 다른 브라우저·실기기 터치는 이번 확인 범위에 포함하지 않았다.

## 5단계 브라우저 확인 (2026-10-15)

- 일반 Chrome 연결은 `Unable to load browser request-header policy`로 실패해 별도 임시 헤드리스 Chrome에서 검사했다.
- 후보 추가·수정·삭제 후 새로고침 복원, 잘못된 입력의 저장 제외, 프리셋 저장·불러오기·삭제와 재로딩, 중복 이름의 실제 확인창 승인·취소, 프리셋 복사본 유지를 확인했다.
- 잘못된 JSON·버전·구조·ID·중복 ID·이름·가중치·색상·후보 수·프리셋 데이터는 기본 후보로 복구하고 손상 원본을 보존했다. 접근 거부와 쓰기 실패를 주입해도 화면 조작이 유지됐다. 정상 데이터와 오류 입력은 별도 브라우저 컨텍스트로 분리하고 검사 사본은 /tmp에 보존했다.
- 회전 중 프리셋 조작 차단과 종료 후 복구를 확인했다. 360px에서 scrollWidth=clientWidth=360, body.scrollWidth=360이고 페이지 JavaScript 오류는 0건이었다.
- 기존 열린 탭 자체, 다른 브라우저·실기기 터치, GitHub Pages 주소에서의 저장은 미확인이다. 저장 실패는 합성 예외 주입으로 확인했으며 실제 디스크 용량 소진은 수행하지 않았다.
